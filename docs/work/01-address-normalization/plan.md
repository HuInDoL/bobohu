# 01. 주소 정리: 구현 계획

> 단계: 2/4 구현 계획 · 작성일: 2026-09-26
> 근거: [research.md](research.md)
> 다음 단계: 사용자 피드백 (`feedback.md`). 피드백을 받기 전에는 구현하지 않는다.

## 1. 전제
- 현재 CSV(2022-12-31 기준)로 진행한다. 최신 파일이 생기면 규칙을 다시 점검한다.
- 원본 CSV는 저장소에 그대로 둔다(이용허락범위 제한 없음).

## 2. 이번 작업의 범위
| 포함 | 제외 (다른 작업에서) |
|---|---|
| 주소 문자열 하나를 받아 **정리된 주소, 시·도, 시·군·구**를 돌려주는 로직 | CSV 읽기, DB 저장 (작업 02) |
| 시·도 이름 표준화 (별칭, 누락, 행정구역 변경) | 시설 유형 추정 (작업 02) |
| 상세주소(동·호·층, 괄호, 건물명) 제거 | Geocoding 호출과 좌표 저장 (작업 03) |
| 단위 테스트 | 그룹홈 공개 정책, 조회 API (작업 04) |

DB 스키마는 바꾸지 않는다. 상세주소 컬럼을 만들지 않기로 했기 때문이다.

## 3. 결정 사항 (추천안)
research.md 6장의 결정 사항에 대한 추천이다. **피드백 단계에서 확정한다.**

| # | 결정 | 추천 | 이유 |
|---|---|---|---|
| 1 | 정리 수준 | **B. Geocoding이 성공할 만큼만** | 표준 주소와 시·군·구는 Geocoding 응답(`roadAddress`, `SIGUGUN`)이 더 정확하다. 규칙을 끝없이 늘리지 않는다. 다만 시·도는 규칙이 적고(17개) 확실해서 이번에 표준화한다 |
| 2 | 상세주소 | **버린다** (사용자 결정) | `address`에는 건물번호까지만 남긴다 |
| 2-1 | `address_raw`의 호수 | **보존하되 API로 내보내지 않는다** | 원본 CSV가 이미 공개되어 있어 지워도 효과가 작고, 규칙을 고친 뒤 다시 처리할 수 있어야 한다. "내보내지 않는다"는 작업 04의 응답 DTO에서 지킨다 |

| 5 | `sigungu` 표기 | **`천안시 동남구`처럼 시와 구를 함께** | 구 이름만 쓰면 다른 도시의 같은 이름(예: 여러 도시의 `동구`, `남구`)과 구분할 수 없다 |
| 6 | 도로명주소 API | **쓰지 않는다** | 승인 절차가 필요하고, 네이버 Geocoding으로 표준 주소를 얻을 수 있다 |

## 4. 설계

### 4.1 파일 구성
```
server/src/main/java/com/bobohu/facility/address/
├── Sido.java                 # 시·도 17개와 별칭 (enum)
├── NormalizedAddress.java    # 결과 (record)
└── AddressNormalizer.java    # 정리 로직
server/src/test/java/com/bobohu/facility/address/
├── SidoTest.java
└── AddressNormalizerTest.java
```
- `facility.address` 패키지로 나눈다. 주소 규칙은 시설 엔티티와 독립적으로 바뀌기 때문이다.
- **Spring에 의존하지 않는 순수 Java 클래스**로 만든다. DB나 컨테이너 없이 밀리초 단위로 테스트할 수 있다.

### 4.2 `Sido` (enum)
17개 시·도의 공식 이름과 별칭을 가진다.
```java
public enum Sido {
    SEOUL("서울특별시", "서울시", "서울"),
    BUSAN("부산광역시", "부산시", "부산"),
    ...
    GANGWON("강원특별자치도", "강원도", "강원"),
    JEONBUK("전북특별자치도", "전라북도", "전북"),
    SEJONG("세종특별자치시", "세종시", "세종"),
    ...;

    public static Optional<Sido> fromAlias(String token) { ... }
}
```
- 나중에 지역 필터나 통계에도 쓸 수 있다.
- DB의 `sido` 컬럼에는 **공식 이름 문자열**(`서울특별시`)을 저장한다. 컬럼 타입은 바꾸지 않는다.

### 4.3 `NormalizedAddress` (record)
```java
public record NormalizedAddress(
    String address,         // 정리된 주소. 예: "서울특별시 중랑구 용마산로 271"
    String sido,            // 예: "서울특별시". 알아내지 못하면 null
    String sigungu,         // 예: "중랑구", "천안시 동남구". 알아내지 못하면 null
    boolean roadAddressFound // 도로명과 건물번호를 찾았는지. false면 작업 02에서 확인 대상으로 보고
) {}
```

### 4.4 `AddressNormalizer.normalize(String raw)` 처리 순서
| 순서 | 처리 | 예시 |
|---|---|---|
| 1 | 입력 검증: null, 빈 문자열, 300자 초과는 예외 | |
| 2 | 앞뒤 공백 제거, 연속 공백을 하나로 | `... 149  ` → `... 149` |
| 3 | 괄호와 괄호 안 내용 제거 | `... 16 203호(사직동)` → `... 16 203호` |
| 4 | **시·도 표준화** | `서울시` → `서울특별시`, `충북` → `충청북도`, `강원도` → `강원특별자치도` |
| 5 | **시·도 누락 보완** | `천안시`, `당진시` → 앞에 `충청남도` / `용인시`, `안성시` → 앞에 `경기도` |
| 6 | **관할 변경** | `경상북도 군위군` → `대구광역시 군위군` |
| 7 | 중복 제거 | `제주시 제주시` → `제주시` / `세종특별자치시 세종시` → `세종특별자치시` / `영등포구 서울 영등포구` → `영등포구` |
| 8 | 읍·면과 도로명 분리 | `합덕읍버그내1길193-11` → `합덕읍 버그내1길 193-11` |
| 9 | 도로명 안의 공백 합치기 | `상도로 39길 48` → `상도로39길 48` |
| 10 | 도로명과 건물번호 분리 | `용마산로271` → `용마산로 271` / `동소문로15길99` → `동소문로15길 99` |
| 11 | **상세주소 제거**: 건물번호 뒤는 모두 버린다 | `... 용마산로 271 103동 604호` → `... 용마산로 271` |
| 12 | 시·군·구 추출: 시·도 다음 토큰이 `시`, `군`, `구`로 끝나면 채택. `시` 다음에 `구`가 오면 함께 | `천안시 동남구`. `경상북도 포항 ...`처럼 끝 글자가 없으면 null(Geocoding으로 채움) |

- 도로명을 찾지 못하면(지번 주소 1건 등) 2~9단계까지만 적용한 문자열을 돌려주고 `roadAddressFound=false`로 표시한다.
- 시·도를 알아내지 못하면 `sido=null`로 두고 문자열은 그대로 둔다. 추측으로 채우지 않는다.

### 4.5 검토한 대안
| 대안 | 채택하지 않은 이유 |
|---|---|
| 정규식 하나로 전체 주소 파싱 | 읽기 어렵고 고치기 어렵다. 단계별 작은 규칙이 테스트하기 좋다 |
| 규칙으로 시·군·구 줄임(`포항`)까지 복원 | 경북 13개 지명을 따로 관리해야 한다. Geocoding 응답으로 채우는 편이 정확하다 |
| Spring Bean(`@Component`)으로 등록 | 상태가 없는 순수 로직이라 필요 없다. 작업 02에서 필요해지면 그때 등록한다 |

## 5. 보안과 안전
- **입력 길이 제한(300자)**: 정규식이 긴 입력에서 느려지는 문제(ReDoS)를 막는다. 정규식은 중첩된 반복(`(a+)+` 형태)을 쓰지 않는다.
- **상세주소는 결과에 남기지 않는다**: 앱에 노출되는 `address`에는 건물번호까지만 들어간다.
- 로그에 주소 원문을 남기지 않는다(작업 02에서 실패 목록을 보고할 때는 CSV 연번만 쓴다).

## 6. 테스트 계획
**단위 테스트만 쓴다** (DB, Docker 불필요).

| 테스트 | 내용 |
|---|---|
| `SidoTest` | 모든 별칭이 올바른 시·도로 바뀐다. 모르는 값은 빈 결과 |
| `AddressNormalizerTest` | `@ParameterizedTest`로 **실제 CSV에서 뽑은 주소 30건 이상**을 입력과 기대값 표로 검증. 4.4의 처리 순서마다 최소 2건씩 |
| 예외 입력 | null, 빈 문자열, 300자 초과 → 예외 / 도로명 없음 → `roadAddressFound=false` / 시·도 모름 → `sido=null` |

**전체 826건 검증**은 CSV를 읽는 작업 02에서 한다. 이번에는 대표 사례로 규칙을 확정한다.
