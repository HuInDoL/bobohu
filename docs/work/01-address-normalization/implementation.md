## 2. 처리 순서 (최종)
1. 입력 검증 (null, 빈 문자열, 300자 초과 거부)
2. 괄호와 괄호 안 내용 제거
3. **`번지` 제거** (계획에 없던 규칙): `군왕로119번지` → `군왕로119`
4. 토큰 나누기. **토큰 끝의 쉼표와 마침표 제거** (계획에 없던 규칙): `415,` → `415`
5. 시·도 표준화, 시·도 누락 보완, 관할 변경(군위군)
6. 시·도가 한 번 더 나오는 토큰 제거
7. 중복 제거. **줄인 이름 뒤에 정식 이름이 오면 줄인 이름 제거** (계획에 없던 규칙): `포항 포항시` → `포항시`
8. 읍·면과 도로명 분리, 도로명 안의 공백 합치기, 도로명과 건물번호 분리
9. 건물번호까지만 남기기. **건물번호가 없으면 도로명까지만 남기고, 도로명도 없으면 동·호·층 토큰만 뺀다** (계획 보완)
10. 시·군·구 추출

## 5. 계획과 달라진 점
| 계획 | 실제 | 이유 |
|---|---|---|
| 경북의 줄인 시·군 이름(`포항`)은 복원하지 않고 Geocoding에 맡긴다 | **줄인 이름을 지워서 시·군·구까지 채운다** | 리서치 때 앞 두 토큰만 보고 "시"가 빠졌다고 판단했으나, 실제로는 `경상북도 포항 포항시 남구 ...`처럼 **정식 이름이 뒤에 한 번 더** 있었다. 줄인 이름만 지우면 되는 간단한 규칙이라 적용했다 |
| 도로명을 찾지 못하면 정리한 문자열을 그대로 돌려준다 | **도로명까지만 남기거나 동·호·층 토큰을 뺀다** | 그대로 두면 `501호` 같은 호수가 `address`에 남는다. 상세주소를 버린다는 결정에 어긋난다 |
| (없음) | `번지` 제거, 토큰 끝 쉼표·마침표 제거 | 전체 CSV 점검에서 8건이 이 때문에 인식되지 않았다 |
| `AddressNormalizerTest`의 입력은 모두 실제 CSV 값 | **대부분 실제 값, 일부는 형식만 같은 예시** | 시·도 별칭(`인천`, `울산`)이나 명칭 변경(`강원도`)은 규칙마다 실제 주소를 찾기보다 짧은 예시가 읽기 쉽다. 테스트 클래스 주석에 밝혔다 |

## 6. 구현 중 발견한 문제
- **도로명 판별 규칙 버그**: 처음 쓴 정규식 `[가-힣0-9]*[가-힣](로|길)`은 "로"나 "길" 바로 앞이 한글이어야 해서 `봉선2로`, `자양로44길`처럼 숫자 뒤에 오는 도로명을 놓쳤다. 테스트를 돌리기 전 코드 검토에서 발견해 `(?=.*[가-힣])[가-힣0-9]+(로|길)`로 고쳤다. 테스트 실패 전에 잡아서 트러블슈팅 기록은 남기지 않는다.

## 7. 보안과 안전 점검
- 입력 길이 300자 제한 테스트 있음
- 정규식에 중첩 반복 없음 (ReDoS 위험 낮음)
- 결과 `address`에 동·호·층이 남지 않음을 826건 전체에서 확인
- 로그 출력 없음

## 9. 확인용 시각화 페이지
사용자 요청으로 정리 결과를 눈으로 확인하는 페이지를 만들었다. 프론트엔드는 먼저 만들고 피드백을 받기로 했다.
- 형태: 확인용 웹 페이지 한 장 (앱이나 Next.js가 아님). claude.ai 비공개 Artifact로 게시
- 내용: 요약 수치, 시·도별 시설 수, 적용된 정리 종류별 건수, 사람이 확인할 주소 7건, 원본과 정리 결과 비교 표(검색, 시·도, 정리 종류, 확인 필요 필터)
- 데이터: 826건 정리 결과를 JSON으로 페이지에 넣었다. "적용된 정리" 분류는 원본과 결과를 비교해 추정한 값이다
- 코드와 데이터는 저장소에 넣지 않았다. 필요하면 피드백 후 결정한다
