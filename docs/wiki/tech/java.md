# Java

> JVM 위에서 실행되는 객체지향 언어. 이 프로젝트의 서버 언어다.

## 개념
Java 코드는 바이트코드(`.class`)로 컴파일되고, JVM(Java Virtual Machine)이 이를 실행한다. JVM만 있으면 어떤 OS에서도 같은 코드가 돈다("Write Once, Run Anywhere"). 정적 타입 언어이고 가비지 컬렉터(GC)가 메모리를 자동으로 관리한다.

## 핵심 내용
- **JDK, JRE, JVM**: JDK는 개발 도구(컴파일러 포함) 전체, JRE는 실행 환경, JVM은 바이트코드를 실제로 실행하는 가상 머신이다.
- **릴리스 주기**: 6개월마다 새 버전이 나오고, 2년마다 LTS(Long-Term Support) 버전이 나온다. LTS 버전은 17, 21, 25다.
- **17 이후 주요 기능**

| 버전 | 기능 |
|---|---|
| 16 | `record`: 불변 데이터 클래스 |
| 17 | `sealed` 클래스: 상속할 수 있는 클래스를 제한 |
| 21 | 가상 스레드(Virtual Threads), `switch` 패턴 매칭, Sequenced Collections |
| 24 | JEP 491: `synchronized` 안에서도 가상 스레드가 캐리어 스레드에 고정되지 않음 |
| 25 | Scoped Values 정식 도입, 생성자에서 `super()` 호출 전에 코드 작성 가능(Flexible Constructor Bodies), 간결한 소스 파일과 인스턴스 `main` 메서드 |

- **가상 스레드**: OS 스레드보다 훨씬 가벼운 JVM 관리 스레드다. 요청마다 스레드를 하나씩 쓰는 방식(thread-per-request)을 유지하면서도 동시에 처리할 수 있는 요청 수를 크게 늘린다. Spring Boot에서는 `spring.threads.virtual.enabled=true`로 켤 수 있다.

## 이 프로젝트에서 사용한 방법
- **버전**: Java 25 (LTS). 선택 이유는 [버전 및 호환성](../versions.md#java-25)을 참고한다.
- **왜 Java인가**: 금융 IT 취업이 목표이고, 국내 은행권 백엔드는 대부분 Java/Spring이다. 개발자가 이미 알고 있는 언어를 깊게 파고드는 것이 목표다.
- **어디에 쓰는가**: 서버 전체 (구현 후 경로 추가)

## 트레이드오프
| 장점 | 단점 |
|---|---|
| 금융권과 대기업에서 표준처럼 쓰여 채용 시장이 넓다 | Kotlin 같은 최신 언어보다 코드가 길다 |

| 생태계(Spring, 라이브러리, 도구)가 매우 성숙하다 | JVM 시작 시간과 메모리 사용량이 Go 같은 언어보다 크다 |
| 하위 호환성이 강하다 | |

## 대안 기술
| 대안 | 특징 | 선택하지 않은 이유 |
|---|---|---|
| Kotlin (서버) | Java와 호환되고 더 간결하며 null 안전성 제공. 핀테크 회사에서 사용 증가 | 금융권 채용 공고는 아직 Java가 기본이다. Kotlin은 앱에서 경험한다 |
| Go | 가볍고 빠르며 동시성 처리가 쉽다 | 국내 금융권 수요가 적다 |
| Node.js (TypeScript) | 프론트엔드와 언어를 통일할 수 있다 | 금융권 백엔드 수요가 적다 |
| Python | 간결하고 데이터나 AI 분야에 강하다 | 대규모 트랜잭션 서버에서는 Java만큼 쓰이지 않는다 |

## 면접에서 나올 만한 질문
- Q. Java 몇 버전을 썼고, 왜 그 버전을 골랐나요?
  - A. [버전 및 호환성의 면접 대비 답변](../versions.md#면접-대비-java-몇-버전-썼어요-왜요) 참고
- Q. LTS 버전이 무엇이고, 왜 LTS를 써야 하나요?
  - A. 장기간 보안 패치와 버그 수정을 받는 버전입니다. LTS가 아닌 버전은 다음 버전이 나오면 6개월 만에 지원이 끝나서, 운영 서비스에서 계속 쓰기 어렵습니다.
- Q. 가상 스레드는 기존 스레드와 무엇이 다른가요?
  - A. 기존 플랫폼 스레드는 OS 스레드와 1:1로 대응해서 생성 비용이 크고 개수에 한계가 있습니다. 가상 스레드는 JVM이 관리하는 가벼운 스레드라, I/O를 기다리는 동안 캐리어 스레드를 반납합니다. 그래서 적은 OS 스레드로도 많은 요청을 동시에 처리할 수 있습니다.
