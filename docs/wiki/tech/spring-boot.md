# Spring Boot

> Spring Framework 기반 애플리케이션을 설정을 최소화해서 바로 실행할 수 있게 해주는 도구. 이 프로젝트의 서버 프레임워크다.

## 개념
**Spring Framework**는 Java 엔터프라이즈 애플리케이션을 만들기 위한 프레임워크다. 핵심은 객체의 생성과 연결을 개발자가 아니라 컨테이너가 맡는 **IoC(제어의 역전)**와 **DI(의존성 주입)**다.
**Spring Boot**는 Spring을 쓰려면 필요했던 복잡한 설정을 자동화한 도구다.

## 핵심 내용
- **IoC 컨테이너와 DI**: 객체(Bean)를 스프링 컨테이너가 만들고 필요한 곳에 주입한다. 객체 간 결합도가 낮아지고 테스트하기 쉬워진다. 생성자 주입을 기본으로 쓴다.
- **AOP(관점 지향 프로그래밍)**: 트랜잭션, 로깅처럼 여러 곳에 공통으로 필요한 기능을 비즈니스 로직과 분리한다. `@Transactional`이 대표적인 예다.
- **자동 설정(Auto-configuration)**: 클래스패스에 있는 라이브러리를 보고 필요한 Bean을 자동으로 등록한다.
- **스타터(Starter)**: `spring-boot-starter-web`처럼 관련 의존성을 한 묶음으로 제공한다. 버전 호환도 Boot가 관리한다.
- **내장 서버**: Tomcat이 들어 있어 별도 설치 없이 `jar` 하나로 실행된다.
- **Spring Boot 4의 주요 변화** (3.x 대비)
  - Spring Framework 7, Jakarta EE 11(Servlet 6.1, Tomcat 11) 기반
  - JSON 처리 기본 라이브러리가 Jackson 3로 바뀜 (확인 필요)
  - JSpecify 기반 null 안전성 어노테이션 도입
  - 자동 설정 모듈이 더 작게 나뉨

## 이 프로젝트에서 사용한 방법
- **버전**: 4.1.x. 선택 이유는 [버전 및 호환성](../versions.md#spring-boot-41)을 참고한다.
- **역할**: Android 앱과 웹이 함께 쓰는 REST API 서버. 화면(HTML)은 만들지 않고 JSON만 응답한다. 그래야 웹 프론트엔드 기술을 나중에 무엇으로 정하든 서버를 고칠 필요가 없다.
- **어디에 쓰는가**: 구현 후 경로 추가

## 트레이드오프
| 장점 | 단점 |
|---|---|
| 국내 금융권, 대기업 백엔드의 사실상 표준 | 자동 설정이 많아서 내부 동작이 보이지 않는다. 문제가 생기면 원인 찾기가 어렵다 |
| 보안, 트랜잭션, 데이터 접근 등 필요한 기능이 거의 다 있다 | 가벼운 프레임워크보다 시작 시간과 메모리 사용량이 크다 |
| 자료와 커뮤니티가 매우 많다 | 배울 개념(IoC, AOP, 프록시 등)이 많다 |

## 대안 기술
| 대안 | 특징 | 선택하지 않은 이유 |
|---|---|---|
| Quarkus, Micronaut | Java 기반. 시작이 빠르고 메모리를 적게 써서 클라우드 네이티브 환경에 강하다 | 국내 채용 수요가 적다 |
| NestJS (Node.js) | TypeScript 기반. 구조가 Spring과 비슷하다 | Java 역량 강화라는 목표와 맞지 않는다 |
| Django, FastAPI (Python) | 빠르게 만들 수 있다 | 금융권 수요가 적다 |

## 면접에서 나올 만한 질문
- Q. Spring과 Spring Boot의 차이는?
  - A. Spring은 DI, AOP 같은 핵심 기능을 제공하는 프레임워크입니다. Spring Boot는 여기에 자동 설정, 스타터, 내장 서버를 더해 설정 없이 바로 실행할 수 있게 만든 도구입니다.
- Q. DI를 쓰면 무엇이 좋은가요? 왜 필드 주입보다 생성자 주입을 권장하나요?
  - A. 객체가 의존 대상을 직접 만들지 않아 결합도가 낮아지고, 테스트할 때 가짜 객체로 바꿔 끼우기 쉽습니다. 생성자 주입은 의존성을 `final`로 선언해 불변으로 만들 수 있고, 빠진 의존성을 객체 생성 시점에 바로 알 수 있습니다.
- Q. `@Transactional`은 어떻게 동작하나요? 같은 클래스 안에서 호출하면 왜 적용되지 않나요?
  - A. Spring AOP가 프록시 객체를 만들어서 메서드 앞뒤로 트랜잭션을 시작하고 커밋합니다. 같은 클래스 안에서 호출하면 프록시를 거치지 않고 실제 객체를 바로 호출하기 때문에 적용되지 않습니다.
