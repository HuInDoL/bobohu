# 후원

> 상태: 계획 중. **법적 검토가 끝나기 전에는 금전을 직접 다루는 기능을 만들지 않는다.**

## 원칙
1. **법적 테두리 안에서만 진행한다.** 법적으로 불가능하거나 불확실한 기능은 만들지 않는다.
2. 플랫폼이 돈을 직접 다루기 어렵다면 **보육원과 후원자를 직접 연결만** 해도 충분하다.
3. 후원이 이루어진다면 **후원 내역, 사용 내역, 사용 계획을 정확하고 세세하게 기록**한다.

## 법적 검토 (2026-09-25 조사, 전문가 검토 필요)

| 법률 | 핵심 내용 | 이 서비스와의 관계 |
|---|---|---|
| 기부금품의 모집ㆍ사용 및 기부문화 활성화에 관한 법률 (기부금품법) | 정보통신망 등으로 불특정 다수에게 **1천만원 이상** 기부금품을 모집하려면 모집·사용계획서를 작성해 행정안전부 또는 시·도에 **등록**해야 한다. 요청하지 않았는데 자발적으로 내는 기탁은 규제 대상이 아니다. 적용 여부는 모집 목적, 방식 등에 따라 개별 판단한다 | **플랫폼이 후원금을 모아서 전달**하면 모집 등록 대상이 될 수 있다 |
| 사회복지사업법 제45조 (후원금의 관리) | 시설장은 후원금 수입과 사용 내역을 명확히 관리해야 한다. 영수증 발급, 연 1회 이상 후원자에게 수입·사용 내용 통보, 시·군·구에 수입·사용결과 보고, 게시판과 홈페이지에 3개월간 공개 의무가 있다 | **시설은 이미 후원금 기록 의무가 있다.** 우리 서비스가 이 의무를 돕는 도구가 될 수 있다 |
| 전자금융거래법 등 | 남의 결제 대금을 받아서 정산해 주는 일은 전자금융업 등록이 필요할 수 있다 (확인 필요) | 플랫폼이 결제를 받고 시설에 나눠 주는 구조는 추가 검토가 필요하다 |

## 운영 방식

### A안: 직접 연결 (우선 진행)
**플랫폼은 돈을 받지도, 보관하지도, 전달하지도 않는다.**
- **금전 후원**: 시설의 후원금 전용 계좌나 시설 자체 후원 페이지로 후원자를 연결한다. 후원자는 시설에 직접 입금한다.
- **물품 후원**: 시설이 등록한 필요 물품 목록을 보고, 후원자가 후원 약속을 한 뒤 시설로 직접 보낸다.
- **플랫폼의 역할**: 정보 제공, 연결, 그리고 **투명성 기록 도구**
- 법적 부담이 가장 적어서 먼저 진행한다.

### B안: 플랫폼 결제 연동 (보류)
플랫폼 안에서 결제까지 끝내는 방식이다. 기부금품법상 모집 등록, 전자금융 관련 규제, 기부금 영수증 발급 주체 문제를 **법률 전문가에게 확인한 뒤에만** 진행한다. 결제 흐름 초안은 [아키텍처](../architecture.md#54-금전-후원-b안-보류)에 있다.

## 투명성 기록 (후원 내역, 사용 내역, 사용 계획)

### 기록하는 것
| 기록 | 입력하는 사람 | 내용 |
|---|---|---|
| 후원 내역 | 후원자가 등록, 시설이 입금이나 수령 확인 | 후원자, 시설, 금액 또는 물품, 날짜, 확인 상태 |
| 사용 계획 | 시설 담당자 | 목적(예: 겨울 난방비), 예정 금액, 예정 시기 |
| 사용 내역 | 시설 담당자 | 사용 날짜, 항목, 금액, 연결된 사용 계획, 증빙(영수증) |
| 정기 보고 | 시설 담당자 | 기간별 후원금 수입과 사용 결과 요약 (사회복지사업법상 보고와 형식을 맞추는 것을 검토) |

### 기록 원칙 (금융 시스템의 원장 방식)
- **한 번 기록한 내역은 수정하거나 삭제하지 않는다(append-only).** 틀린 내용은 원래 기록을 두고 **정정 기록**을 새로 추가한다. 누가 언제 무엇을 바꿨는지 모두 남는다.
- **잔액은 저장하지 않고 계산한다.** 잔액은 후원 수입 합계에서 사용 합계를 빼서 구한다. 따로 저장한 값과 실제 내역이 어긋날 일이 없다.
- **금액은 원 단위 정수**(`long` 또는 `BigDecimal`)로 다룬다. 부동소수점(`double`)은 쓰지 않는다.
- **상태 변화를 명시적으로 관리한다.** 후원 약속 → 입금 확인 → (사용 계획에 배정) → 사용 완료
- 증빙 사진에 개인정보(카드 번호, 받는 사람 주소 등)가 보이면 가리고 올리도록 안내한다.

### 후원자가 볼 수 있는 것
- 내가 후원한 내역과 시설의 확인 여부
- 후원한 시설의 **전체 후원금 수입, 사용 내역, 사용 계획**
- 돈은 섞여서 쓰이므로 "내 돈이 정확히 어디에 쓰였는지"를 1원 단위로 추적하기는 어렵다. 목적을 정해서 후원하는 **지정 후원**(예: "겨울 난방비 계획에 후원")은 그 계획의 사용 내역과 연결해서 보여주는 방식을 검토한다.

## 요구사항 (A안 기준)
- [ ] 시설 상세 화면에 후원 방법(전용 계좌, 시설 후원 페이지) 표시
- [ ] 시설 담당자의 필요 물품 목록 등록
- [ ] 후원자의 후원 등록 (금액 또는 물품), 시설의 확인
- [ ] 시설 담당자의 사용 계획과 사용 내역 등록
- [ ] 시설별 후원금 수입, 사용 현황 공개 화면
- [ ] 모든 기록의 변경 이력(정정 기록) 보존

## 사용 기술
- [Spring Boot](../tech/spring-boot.md), [PostgreSQL](../tech/postgresql.md)
- 트랜잭션과 동시성 제어(같은 후원을 두 번 확인하는 경우 등)는 구현할 때 정리한다.

## 확인할 것
- [ ] A안(직접 연결)이 기부금품법상 "모집"에 해당하지 않는지 법률 전문가 확인
- [ ] 시설 후원금 계좌 정보를 공개하는 것에 대한 시설 동의 절차
- [ ] 사회복지사업법상 후원금 수입·사용결과 보고서 서식
- [ ] B안을 한다면 필요한 등록과 인허가
